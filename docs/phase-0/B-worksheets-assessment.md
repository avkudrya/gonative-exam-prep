# B. Worksheet Generator и движок Edu — что переиспользует Exam Prep

**Статус:** черновик v1 (2026-11-22), только чтение. **ТЗ:** §3.2, §12, §26 B.
**Источники:** MultiAdmin `app/Services/Edu/*`, `app/Services/Worksheets/*`, `config/edu_models.php`;
WG `PLAN.md`, `docs/phase-0/*`, `benchmarks/REPORT.md`. Состояние WG — на 2026-11-22; проект активно
меняется, перед интеграцией сверять заново.

## 1. Итог

| Вывод | Следствие |
|---|---|
| Бэкенд WG — это `Edu` (общий движок) + `Worksheets` (продукт) внутри MultiAdmin; сайт и PDF-рендер — в репо WG | Интегрируемся с `Edu` на уровне PHP-фасадов, а не по HTTP с сайтом WG |
| AI-слой `Edu\Ai` зрелый: три вендора, маршрутизация по задачам, учёт стоимости и бюджеты, идемпотентные шаги | Пайплайн оценки эссе строим на нём; новых AI-клиентов не пишем |
| Есть раннеры бенчмарков и калибровки (`Edu\Bench`) и отработанная методика (разные вендоры, слепая проверка, денежные лимиты) | Фаза 1 сразу опирается на эту инфраструктуру |
| Банк грамматики в production; грамматика Мнемоника уже импортирована в Edu | Упражнения на слабые места берём из банка; к Мнемонику напрямую не обращаемся (ТЗ §3.3) |
| WG ориентирован на печать: у типов упражнений есть ключ ответа, но нет проверки ответа ученика | Онлайн-практику (ответ → проверка → результат) нужно добавить; общую часть — в `Edu` |
| Автогенерация по запросу пользователя в production ещё закрыта (флаги выключены, открыты гейты R1–R5 WG) | На старте — только проверенные задания из банка; генерация под пользователя — когда WG закроет гейты |

## 2. Что реализовано (переиспользуем как есть)

| Компонент | Где | Для Exam Prep |
|---|---|---|
| `LlmClient` + `OpenAiLlmClient`, `AnthropicLlmClient`, `XaiLlmClient`, `LlmClientFactory` | `Edu/Ai` | Вызовы моделей для оценки и проверки |
| `ModelRouter` / `ModelRoute` + `config/edu_models.php` (задачи, кандидаты, `avoid` вендора, `purpose_routes`, языковые переопределения) | `Edu/Ai` | Новые задачи `assess.*`, `validate.assessment` — в том же конфиге; валидатор всегда другого вендора |
| `MeteredLlm`, `LlmUsage`, `ModelPricing` → `ai_usage_events` (токены, стоимость) | `Edu/Ai` | Стоимость каждой оценки (ТЗ §20, §22) |
| `ReservedRunBudget`, `BudgetExceededException` | `Edu/Ai` | Денежный лимит на прогон бенчмарка и на оценку |
| `StepRunner` (шаги с ключом идемпотентности) | `Edu/Ai` | Повтор оценки не повторяет оплаченные вызовы |
| `Bench*`, `Calibration*` | `Edu/Bench` | Каркас бенчмарка Фазы 1: датасет, прогон, метрики, отчёт |
| `LanguageProfile` (`normalizeAnswer`, `answersEquivalent`), `EnglishProfile` | `Edu/Languages` | Детерминированная проверка ответов в онлайн-практике |
| 12 типов упражнений (`MultipleChoice`, `GapChoice`, `GapFill`, `ErrorCorrection`, `Transformation`, `Ordering`, `WordForms`, `Matching`, `VocabTranslation`, `SentenceTranslation`, `Reading`, `WordList`) с `payloadSchema`, `validate`, `answerKey` | `Edu/Exercises` | Формат упражнений практики — не изобретаем свой |
| Темы, маппинги, спецификации тем, ревью и провенанс (`Topic`, `TopicMapping`, `TopicSpec`, `ContentReview`, `ItemSource`) | `Edu`, модели `Models/Multi/Edu` | Навык из оценки (`grammar.articles`) → тема Edu → задания |
| Значения и переводы (`Sense`, `SenseTranslation`, `TextTranslation`) | `Edu/Semantics` | Переводы объяснений и выражений на язык пользователя |
| Квоты, планы и учёт периода (`WorksheetQuota`, `WorksheetPlans`, `ws_usage_periods`) и биллинг (`Worksheets/Billing`) | `Worksheets` | Образец для `Exam/Quota` и `Exam/Billing` (копируем подход, не импортируем код) |

Банк в production (по WG `PLAN.md`, 2026-11-22): каталог 16 / 128 / 3031, пригодно к выдаче 3238 заданий
(из них AI-общих 2218); идёт наполнение лексических воркшитов.

## 3. Что частично, экспериментально или отсутствует

| Что | Статус | Что делать Exam Prep |
|---|---|---|
| Генерация воркшита по запросу пользователя | Код есть, в production выключена; гейты R1–R5 WG открыты | На старте не зависеть; использовать банк |
| Проверка ответа ученика (`checkAnswer`) | В интерфейсе `ExerciseType` нет; задумывалась «для интерактива в будущем» (WG E §3.2). Владелец планирует онлайн-проверку (2026-11-22), сроки не определены | Не строить свою: согласовать с планом владельца общий `AnswerChecker` в `Edu` по `answerKey` + `LanguageProfile`; Exam Prep — его потребитель (ТЗ §12) |
| Чтение (`Reading`) | Ограничено, только из банка | Не нужно до Фазы 7 |
| Английская грамматика по навыкам IELTS (артикли, времена, согласование) | Темы есть в каталоге; соответствие нашим навыкам не проверено | Таблица соответствия «навык → тема Edu» (P0.2) |
| Teaching workspace (ученики, занятия) | Локально / частично выложено | Вне объёма Exam Prep |

## 4. Рекомендуемая граница интеграции

```
Exam\Learning\PracticeRecommender
   └─ Edu фасад BankQuery: задания по (язык, тема, CEFR, тип), исключая уже решённые пользователем
   └─ (позже) Edu генерация с purpose = exam_practice, когда WG откроет генерацию по запросу
Exam\Learning\PracticeSession  ← новое: выдача заданий онлайн, ответы, результат
   └─ Edu AnswerChecker (новое, общее)
   └─ результат → ex_skill_observations (обновление профиля навыков)
```

Логику упражнений не форкаем; продуктовое состояние (назначения, попытки практики) живёт в `ex_*`.
Экспорт в PDF через WG — возможное расширение позже («распечатать практику»).

## 5. Проверить (P0.2)

1. Реальный список тем en и их уровни; есть ли темы под артикли, времена, согласование, предлоги,
   сложные предложения, пассив.
2. Как выбрать «пригодные к выдаче» задания: статусы и флаги прав (`publication_allowed`, CEFR, servable).
3. Нужен ли `Edu` фасад «задания по теме для пользователя» или его можно собрать из того, что использует
   `Worksheets/Bank`.
4. Как `Edu\Bench` хранит датасеты и результаты; подходит ли он для эссе (длинный текст, оценки по
   критериям) или нужен свой `Exam\Bench` поверх общих `StepRunner`/`MeteredLlm`.
