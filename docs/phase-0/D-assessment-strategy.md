# D. Стратегия AI-оценки IELTS Writing

**Статус:** черновик v1 (2026-11-23). Окончательный выбор пайплайна и моделей — по итогам бенчмарка Фазы 1 (E).
**ТЗ:** §8, §26 D. **Основано на:** [D1](D1-ielts-writing-spec.md) (проверенная спецификация), [E1](E1-reference-data.md)
(данные), [ADR-003](../decisions/ADR-003-score-claims.md) (что показываем), [H](H-edu-integration.md) §7 (AI-слой Edu).

## 1. Принципы

1. **Сначала детерминированное, потом AI.** Всё, что дескрипторы говорят прямо, считает код (правила рубрики).
2. **Модель находит доказательства, полосу считает код.** Вариант «назови балл» — только базовая линия для сравнения.
3. **Каждое утверждение — с цитатой** из текста пользователя; цитата проверяется кодом (`checkAssessmentIntegrity`).
4. **Проверяет другой вендор.** Валидатор не видит полос, только находки, и не тот же провайдер (`avoid` в `ModelRouter`).
5. **Своё руководство по оценке.** Дословный текст дескрипторов в промптах не используем, пока нет разрешения IELTS
   Partners ([D1](D1-ielts-writing-spec.md), «Правовой момент»).
6. **Эссе — данные, не инструкции.** Текст передаётся отдельным полем JSON; инструкции внутри эссе отмечаются находкой
   и не исполняются.

## 2. Пайплайн оценки Task 2 (кандидат для бенчмарка)

| # | Шаг | Кто | Результат |
|---|---|---|---|
| 0 | Нормализация, подсчёт слов (`whitespace-v1`), абзацы | Код | Текст для офсетов, число слов |
| 1 | **Правила рубрики:** ≤ 20 слов → Band 1 по всем критериям (дальше не идём); весь текст не на английском → Band 0; фрагменты, совпадающие с заданием (≥ 8 слов подряд), не засчитываются; списки и маркеры вместо связного текста → находка; короче 250 слов → предупреждение | Код | Ранний выход или ограничения |
| 2 | **Проверка задания** (своё задание пользователя): похоже ли на задание Task 2, полное ли оно, нет ли в нём инструкций модели | AI, дешёвая модель | Принять / предупредить / отклонить |
| 3 | **Оценка по критерию** (×4, параллельно): по руководству для критерия модель отмечает выполненные признаки каждой полосы и найденные ограничители, к каждому — цитату; плюс находки (ошибки с цитатой, исправлением, объяснением, навыком, серьёзностью) | AI, вендор A | Чек-лист признаков, ограничители, находки |
| 4 | **Полоса критерия:** наивысшая полоса, все положительные признаки которой выполнены → минус ограничители ([D1](D1-ielts-writing-spec.md), таблица ограничителей) → диапазон (если признаки соседних полос выполнены частично — `low`/`high`) | Код | `estimate` критерия |
| 5 | **Целостность:** схема, каждый критерий один раз, цитаты совпадают с текстом, значения на шкале. Ошибочное — один ремонт, затем отбрасывается | Код (+ AI на ремонт) | Чистый результат |
| 6 | **Независимая проверка находок:** для каждой — верна / ложное исправление / не подтверждена текстом; опционально — пропущенные серьёзные ошибки | AI, вендор B ≠ A | Снятые находки, понижение уверенности |
| 7 | Сведение: полоса за задание — среднее критериев (храним без округления), показ — `presentEstimate` (ориентировочная сетка) | Код | `AssessmentResult` |
| 8 | Наблюдения навыков из находок; рекомендации — отдельно (документ F) | Код | `ex_skill_observations` |

**Язык объяснений:** цитаты и исправления — на английском; объяснения — сразу на языке объяснений пользователя
(ru/uk/en) в шаге 3. Бенчмарк проверяет качество объяснений и на русском (выборочно).

**Базовая линия для сравнения:** P0 — один вызов на всё эссе с прямыми полосами; P1 — четыре вызова с прямыми полосами;
P2 — описанный пайплайн. Каждый — с шагом 6 и без.

## 3. Руководство по оценке (своими словами)

- Для каждого критерия и полосы 4–9 — 3–6 проверяемых признаков в нашей формулировке и список ограничителей.
  Полосы 0–3 покрываются правилами шага 1 и ограничителями.
- Пишется в Фазе 1 (P1.1): черновик готовит Claude по смыслу официальных дескрипторов, проверяет второй вендор
  на смысловое соответствие, утверждает владелец. Хранится версионированным конфигом в MultiAdmin
  (`assessment_guide.ielts-writing-task-2@v1`); версия пишется в результат.

## 4. Модели и маршрутизация (кандидаты, решает бенчмарк)

Задачи в `config/edu_models.php`: `assess.precheck`, `assess.criterion`, `assess.repair`, `assess.validate`.

| Роль | Кандидаты (цены за 1M токенов вход/выход, по `config/edu_models.php`) |
|---|---|
| Оценка по критерию | Claude Haiku 5.5 ($0.10/$0.50), Claude Sonnet 5.5 ($2/$10), Claude Opus 5.5 ($4/$20), GPT-5.4 ($2.50/$15) |
| Проверка находок (другой вендор) | GPT-5.4 mini ($0.75/$4.50), Grok 4.3 ($1.25/$2.50), Claude Haiku 5.5 — если оценивает не Anthropic |
| Проверка задания, ремонт | Самая дешёвая модель, прошедшая бенчмарк |

Опыт WG: Claude резко лучше других как валидатор заданий, а Haiku 5.5 почти не уступал Opus при цене в 40 раз ниже.
Для эссе это не переносится автоматически — поэтому бенчмарк.

## 5. Ограничения и защита

- **Бюджет на одну оценку:** жёсткий предел в `GenerationRun.budget_usd` (стартовая гипотеза — $0.25), превышение →
  `partial`, без повторных платных вызовов (`StepRunner`).
- **Повтор того же текста** того же пользователя с той же версией пайплайна — отдаём сохранённый результат, а не платим заново.
- **Ответ не той формы** (схема) — один ремонт, иначе критерий помечается «не оценён» и попытка — `partial`.
- **Злоупотребления:** квоты и частота — по образцу WG; максимум длины текста (например, 1 000 слов для Task 2).

## 6. Что вне MVP

Task 1 Academic (графики — данные структурой, D1), Task 1 GT (тон и три пункта письма), полная симуляция Writing —
отдельные руководства и бенчмарки в Фазе 5.
