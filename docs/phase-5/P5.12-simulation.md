# P5.12. Полная симуляция Writing

**Дата:** 2026-11-26. Владелец: «закрывай gate P5.11 и переходи к 5.12». План: [P5-plan.md](P5-plan.md), §4.

**Решения владельца:**
- таймер — мягкий по умолчанию, строгий «режим экзамена» по выбору (решение плана, вопрос 4);
- задания — случайная пара из библиотеки, которую ученик ещё не писал; до старта пару можно один раз заменить;
- результат — своя страница: общий диапазон Writing, диапазоны Task 1 и Task 2 и ссылки на два полных разбора.

## 1. Итог

Код готов. Симуляция скрыта за флагом **`EXAM_SIMULATION_ENABLED`**, по умолчанию он выключен.

| Где | Коммит | Тесты |
|---|---|---|
| MultiAdmin | `922b76cd`, **с миграцией**, ещё не отправлен: push — по «да» | Exam 161/161, Unit/Exam 46/46 на PHP 8.4 и 8.2 |
| Этот репозиторий | сайт, см. журнал | сайт 18/18, lint и typecheck чистые |

Денег не потрачено: модель в тестах не вызывается. Каждая живая симуляция тратит две обычные оценки, около $0.14 из квоты.

## 2. Как это работает

**Ученик:**
1. **Writing → «Полный тест Writing».** Кнопка появляется, только когда бэкенд может провести симуляцию хотя бы для одного
   экзамена. Для этого нужен флаг, и оба задания Writing должны оцениваться из библиотеки. У General Training — письмо и
   эссе, у Academic — график и эссе.
2. **Пара заданий.** Система выбирает случайную пару из заданий, которые ученик ещё не писал. Когда они кончатся, она берёт
   любые. Пару можно один раз заменить. Таймер выбирается здесь же: мягкий или строгий.
3. **«Начать тест».** Создаются два черновика, таймер на 60 минут общий. Задания открываются на вкладках, черновики
   сохраняются так же, как в обычном редакторе.
   - **Мягкий таймер:** когда время выходит, ученик видит сообщение «Время вышло» и может дописать.
   - **Строгий таймер:** в 00:00 сайт сам отправляет ответы. Сервер ещё 2 минуты после срока принимает последнее
     автосохранение, потом черновики закрыты.
4. **«Отправить оба задания».** Перед отправкой ученик видит, сколько слов в каждом ответе и сколько разборов уйдёт из
   квоты. Пустой ответ не отправляется и остаётся обычным черновиком.
5. **Сводка.** Пока идут оценки, страница ждёт. Потом показывает:
   - общий ориентировочный диапазон Writing;
   - диапазон каждого задания;
   - ссылки на два обычных полных разбора.

   Общий диапазон показывается, только когда готовы оба разбора.

**Оценка Writing:**
- по агрегации каталога: задание — среднее по четырём критериям, Writing — Task 1 : Task 2 = 1 : 2;
- нижние и верхние границы усредняются отдельно, затем результат расширяется до сетки 0.5 и ширины не меньше 1, как у критериев
  (`EstimatePresenter`, ADR-003);
- пример: Task 1 6, Task 2 7 → 6.67 → «≈ 6–7.5, ориентировочно»;
- общего балла IELTS нет, подпись «не официальный балл».

**Квота.** Две отправки — две обычные оценки. Месячный лимит и деньги проверяются на обе сразу: либо принимаются обе, либо ни
одной. В обоих тарифах одновременно идёт только одна оценка (`concurrent = 1`), поэтому пара симуляции занимает один такой слот.
Тарифы не менялись.

**Ограничения:**
- открытая симуляция у ученика одна, из неё можно выйти, черновики останутся обычными;
- ответ из идущей симуляции нельзя отправить отдельно, только вместе с ней;
- удаление данных Exams удаляет и симуляции.

## 3. Что сделано

**MultiAdmin** (`922b76cd`):
- **Миграция** `2026_11_27_100000_create_exam_writing_sessions_table.php` — одна новая таблица `ex_writing_sessions`. В ней пара
  заданий, режим таймера, срок, две попытки и статус. Текстов нет, они остаются в `ex_attempts`. `--pretend` на локальной
  базе показал только `create table` и `alter table` этой таблицы. Локально не применялась.
- **`WritingSessions`:** выбор пары, замена, старт, выход, совместная отправка. **`WritingEstimate`:** средневзвешенное по
  каталогу.
- **`ExamQuota::admit`:** оценки одной симуляции занимают один слот одновременности. **`SubmitAttempt`:** ответ идущей
  симуляции отправляется только с ней. **`ExamAttempts::saveDraft`:** строгий срок. **`ExamsDataPurger`:** новая таблица.
- **API** `api/exam/writing-sessions` (список, создание, просмотр, swap, start, abandon, submit). В каталоге у секции появились
  `simulation` и `time_minutes`.
- **Тест `WritingSessionTest`, 8 случаев:** флаг, пара без написанных заданий, одна замена, строгий и мягкий таймер, обе
  оценки при `concurrent = 1`, откат при нехватке квоты, сводка и её состояния, выход и удаление данных.

**Сайт:**
- страницы `/ielts/writing/simulation` и `/ielts/writing/simulation/[uuid]`, компонент `simulation.tsx`;
- маршруты BFF, схемы, тексты en/ru/uk;
- сквозной тест `test/simulation.test.mjs`: пара, замена, строгий таймер, два ответа, одна отправка, ожидание, диапазон Writing и
  ссылки на разборы.

## 4. Production — по шагам

1. **Ваше «да» на push MultiAdmin с миграцией** (ADR-004). Пока push не сделан, никакие следующие коммиты MultiAdmin тоже
   не уйдут, потому что ветка одна.
2. **Деплой MultiAdmin** — штатный, с миграцией `2026_11_27_100000_create_exam_writing_sessions_table.php`. Бэкап не нужен:
   миграция только создаёт новую таблицу, как в P4.8. Пока выключен флаг, ничего не меняется. Вместе с этим деплоем
   заработает склейка улучшений из теста 07 (`9f1ac977`).
3. **Деплой сайта** — могу сделать сам, скажите «деплой». Без флага кнопки «Полный тест» на сайте не будет.
4. **Флаг:** `EXAM_SIMULATION_ENABLED=true` в `shared/.env`, затем сброс кэша конфигурации и перезапуск воркера, как в прошлые
   разы.
5. **Живая проверка:**
   - Writing → «Полный тест Writing» → «Подобрать задания» → строгий или мягкий таймер → «Начать тест»;
   - написать оба ответа → «Отправить оба задания»;
   - через минуту-две — общий диапазон и ссылки на оба разбора.

   Две оценки — около $0.14 из вашей квоты. Для бесплатного тарифа (2 разбора в месяц) это вся месячная квота.

**Откат:** выключить флаг. Кнопка исчезает, новые симуляции не создаются. Отправленные ответы доводятся до конца как обычные
попытки.
