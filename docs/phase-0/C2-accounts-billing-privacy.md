## 1. Итог

| Вывод | Следствие |
|---|---|
| WG уже построил продуктовые аккаунты, BFF, права, квоты, оплату Paddle и удаление — **но под один продукт** (`worksheets` зашито в классах, токенах, аудитории) | Главное решение: обобщить это до «продукта из конфигурации» и подключить Exams, а не копировать (п. 5) |
| Подписки Paddle с полной изоляцией продуктов, возвратами и chargeback готовы и проверены в Sandbox | Ежемесячная подписка Exams — конфигурация, а не новый код |
| **Разовых покупок нет:** `transaction.completed` только записывается | Пакеты оценок и «доступ на 30/90 дней» — новая ветка вебхука (п. 3) |
| `product_entitlements` хранит права с точными границами времени и источником | «Доступ на 30/90 дней» ложится в неё без новой таблицы |
| Эссе — личный текст, и **каждая оценка отправляет его AI-провайдеру** (у WG по умолчанию в AI ничего от пользователя не уходит) | Отдельный раздел политики конфиденциальности, отдельные ключи API, срок хранения (п. 4) |

## 2. Аккаунты и BFF (P0.5)

## 3. Оплата и права (P0.6)

### 3.1 Что есть

- `config/billing_products.php`: price id → продукт / план / период для sandbox и production.
- `product_entitlements` + `ProductEntitlement::hasAccess()`: время, статус, продукт, план, окружение Paddle.
- Вебхук: подпись до разбора, блокировка по подписке, дедупликация событий, транзакционные записи, полный возврат
  и chargeback отзывают только связанное право, частичный возврат доступ сохраняет.
- Checkout и портал Paddle с серверной привязкой пользователя и продукта; браузер выбирает только период.
- Квоты WG: календарный месяц UTC, лимиты по видам операций, резервирование до запуска, денежный предел на AI в месяц.

### 3.2 Что добавить для Exams

| # | Что | Как |
|---|---|---|
| B1 | Подписка Exams (если выберем) | Цены в каталоге + обработчик из обобщённого кода (п. 5) |
| B2 | **Доступ на 30/90 дней** — разовая покупка | `transaction.completed` для разовой цены Exams → `product_entitlements` с `ends_at = оплата + N дней`, источник = транзакция; полный возврат отзывает |
| B3 | **Пакет оценок** — разовая покупка | Журнал кредитов `ex_credit_ledger`: начисление по транзакции, списание при запуске оценки (резерв → подтверждение / возврат при сбое), срок действия; полный возврат снимает неизрасходованное |
| B4 | Квоты Exams | По образцу `WorksheetQuota`: оценки, повторные проверки, генерация заданий, денежный предел AI в месяц, параллельные операции |
| B5 | Снятие лимитов GoNative по праву Exams | V2 из [G](G-vocabulary-integration.md) §3.2 |

Модель цен — гипотеза ТЗ §20; конкретные пакеты и цены — после замеров стоимости оценки (документ M).

## 4. Приватность (P0.7)

### 4.1 Что делают провайдеры с данными API (по их документации на 2026-11-23)

| Провайдер | Обучение на данных API | Хранение у провайдера | ZDR (без хранения) |
|---|---|---|---|
| Anthropic | Нет без явного разрешения | По умолчанию не хранится, **кроме «Covered Models» — 30 дней**; среди них несколько моделей Claude 5 | По заявке через отдел продаж; часть моделей Claude 5 под ZDR недоступна |
| OpenAI | Нет (с 2023-03-01), если не включить передачу | Журналы контроля злоупотреблений — до 30 дней | Modified Abuse Monitoring / ZDR — по одобрению OpenAI |
| xAI | Нет без явного разрешения | 30 дней для аудита злоупотреблений | Включается командой в консоли; отключает хранение файлов и ответов на стороне xAI |

Это пересказ документации, а не договоров. Перед запуском перечитать актуальные условия и DPA.
Источники: [Anthropic — API and data retention](https://platform.claude.com/docs/en/build-with-claude/api-and-data-retention),
[OpenAI — Your data](https://developers.openai.com/api/docs/guides/your-data),
[xAI — Security FAQ](https://docs.x.ai/docs/resources/faq-api/security).

### 4.2 Требования к Exam Prep

1. **Политика конфиденциальности Exams** — по структуре WG (`web/src/lib/privacy.ts`, en/ru/uk). Отдельный раздел
   об AI-оценке:
   - что именно отправляется: текст эссе, задание, настройки;
   - кому: провайдеры названы поимённо;
   - обучения нет, хранение у провайдера — до 30 дней;
   - передача за пределы ЕЭЗ — с DPA и стандартными договорными условиями (SCC).
2. **Отдельные ключи API (проекты) для Exams** у каждого провайдера: раздельный учёт и лимиты расходов,
   свои настройки хранения (например, ZDR у xAI). Сейчас `LlmClientFactory` берёт один ключ на провайдера —
   нужна небольшая доработка: ключ по продукту.
3. **Хранение у нас:**
   - эссе хранится, пока существует попытка;
   - пользователь может удалить попытку, и текст удаляется физически; обезличенные числа оценки для аналитики
     стоимости остаются;
   - удаление данных Exams — `ExamsDataPurger` по образцу `WorksheetsDataPurger`, а удаление общего аккаунта
     вызывает его.
4. **Журналы:** текст эссе не попадает в журналы, отчёты об ошибках и `ai_usage_events.meta` — только хэш и длина.
   Проверяется тестом.
5. **Резервные копии:** у WG в политике честно сказано, что срок их хранения не настроен. Для эссе это слабое место:
   стоит задать срок хранения резервных копий для БД `multi` (вопрос владельцу, затрагивает все продукты).
6. **Возраст:** экзамен сдают в основном с 16 лет; согласие на обработку данных в ЕС — с 13–16 лет по странам.
   Минимальный возраст пользователя Exams — вопрос владельцу (условия и регистрация).
7. **Согласия:** условия и политика — версионируются (как у WG); калибровка — отдельное отзываемое согласие (ADR-003);
   рассылки — только по явному согласию (ТЗ §21).

## 5. Главное архитектурное решение: обобщить продуктовый код WG

Сейчас «продукт» зашит в коде WG: `WorksheetAuth`, токен `worksheets-web`, `WorksheetsSubscriptionHandler`,
`WorksheetPlans`, `WorksheetsDataPurger`, `GoNativeAudience` (`signupProduct === 'worksheets'`).

| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. Обобщить** (рекомендую): `config/products.php` (ключ, способность токена, имя cookie, метка регистрации, планы, цены, версия условий, purger) + общие `ProductAuth`, `ProductSubscriptionHandler`, `ProductQuota`, `ProductDataPurger`; классы WG остаются тонкими обёртками | Один код для двух продуктов и следующих; правки безопасности — в одном месте (ТЗ §2.2 «avoid competing implementations») | Трогает работающий код WG: отдельные коммиты без изменения поведения, полный прогон тестов WG (биллинг 15/137, аккаунты, квоты) как защита |
| B. Скопировать под Exams | Не трогает WG | Две копии авторизации, биллинга и удаления; каждая будущая правка — дважды; расхождения в безопасности |

Делать в начале Фазы 2, до кода Exams; по одному блоку (аккаунты → права и биллинг → квоты → удаление).

## Решения владельца (2026-11-23)

1. **Обобщить** продуктовый код WG (вариант A §5), в начале Фазы 2, по блокам, без изменения поведения WG.
2. **Оплата — разовые покупки:** доступ на 30/90 дней без автопродления (B2) и пакеты оценок (B3).
   Подписка (B1) пока не делается. Цены — после замера стоимости оценки (M).
3. **Минимальный возраст — 16+** (условия, регистрация, политика).
4. **Резервные копии:** задать срок хранения бэкапов БД `multi` — отдельная задача в MultiAdmin до запуска
   Exams; в политике указать фактический срок.
