# ADR-003. Что мы утверждаем об оценке

**Статус:** принято владельцем 2026-11-22 (с ориентировочным показом до калибровки).
**ТЗ:** §2.1, §8.5, §9.4, §13.6. **Проверяется в коде:** `presentEstimate` и тесты в `packages/exam-domain`.

## Правила

1. **Любая AI-оценка — диапазон**, а не точка, со статусом калибровки (`uncalibrated` / `calibrated`
   + идентификатор калибровочного прогона).
2. **До калибровки оценка показывается ориентировочно** — «обтекаемо», по решению владельца:
   - Это широкий диапазон на грубой сетке вокруг середины оценки модели. Для критериев IELTS — шаг 0.5
     и ширина не меньше одной полосы: «примерно 5.5–6.5». Сетка задаётся в конфигурации шкалы
     (`approximate`); если её нет, число не показываем.
   - Подпись всегда рядом с числом: «ориентировочно», «не официальная оценка».
   - Число дополняет разбор, а не заменяет его: на первом плане — замечания по критериям с цитатами
     из текста и что исправить.
   - Если бенчмарк Фазы 1 покажет ошибку больше ширины диапазона, сетку расширяем или показ
     выключаем до калибровки.
3. **Калиброванной** оценку критерия делает только прогон на отложенной выборке с оценками
   экзаменаторов, который прошёл пороги из плана бенчмарка (документ E). Ширина показываемого
   диапазона — не меньше измеренной ошибки.
4. **Никогда:** «официальная оценка», «ваш точный балл IELTS», общий балл IELTS по одному Writing,
   прогноз «достигнете 7.0 за N дней», вывод о готовности к экзамену по одной попытке.
5. **Тексты сайта и маркетинга:** можно — «примерная оценка уровня по критериям IELTS»; нельзя —
   «точный калькулятор баллов», пока нет калибровки (ТЗ §9.4).
6. **История не переписывается:** результат хранит версии экзамена, рубрики и пайплайна. Новая
   калибровка не меняет старые результаты задним числом (ТЗ §5.3).

## Путь к калибровке (решение владельца 2026-11-23)

Публичных эссе с оценками экзаменаторов IELTS для коммерческого использования нет ([E1](../phase-0/E1-reference-data.md)).
В продукт закладываем **ввод официального результата пользователем**:

- После даты экзамена из профиля (или в любой момент) пользователь по желанию вводит официальные оценки
  по секциям и дату сдачи. Скан TRF не принимаем: лишние личные данные.
- Отдельное, отзываемое согласие на использование результата для калибровки — не часть общих условий.
  Без согласия результат виден только пользователю: «ваш прогноз и реальный результат».
- Результат сопоставляется с нашими оценками последних попыток до даты экзамена (окно и правила отбора —
  в документе E). Используется только в агрегате: смещение и разброс по критериям; одна запись никогда
  не считается эталоном для конкретного человека.
- Данные самоотчётные и шумные (другой день, другое задание, Writing — это Task 1 + Task 2, а наши попытки
  чаще только Task 2), поэтому они показывают направление и масштаб ошибки, но в одиночку статус
  `calibrated` не дают. Порог «сколько записей и какое согласие с экзаменаторами» задаётся в E.
- Контракт: `reportedResult` и `checkReportedResult` в `packages/exam-domain`; хранение — таблица
  `ex_reported_results` (документ I); удаляется вместе с аккаунтом.

Оценка эссе нанятыми экзаменаторами — отдельное решение после Фазы 1.

Дословный текст дескрипторов в продукте не используем, пока нет разрешения IELTS Partners (владелец
отправит запрос позже); руководство по оценке пишем своими словами.

## Следствие для продукта

Даже при неудачной калибровке продукт можно выпускать: ценность — в доказательном разборе,
профиле ошибок и персональной практике, а не в числе.
