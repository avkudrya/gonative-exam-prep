# E. План бенчмарка Фазы 1 и смета

**Статус:** v1, утверждено владельцем 2026-11-23: лимит **$100**, пороги §3 приняты. Данные и лицензии — [E1](E1-reference-data.md); пайплайны — [D](D-assessment-strategy.md).
**ТЗ:** §9, §26 E. Смета — **оценка до замера токенов**; перед каждым платным этапом — замороженный манифест,
бесплатный подсчёт токенов и «да» владельца с лимитом (как в WG).

## 1. Вопрос, на который отвечает Фаза 1

1. Насколько точны и полезны **находки** (ошибки с цитатами и исправлениями)?
2. Насколько **устойчивы** оценки по критериям между повторами?
3. Насколько оценки по критериям **согласуются с людьми** (ELLIPSE, EWCCE), и насколько широк должен быть
   ориентировочный диапазон (ADR-003)?
4. Сколько стоит одна оценка и сколько она длится?

## 2. Наборы данных

| Набор | Состав | dev / test | Эталон |
|---|---|---|---|
| **S** — вставленные ошибки | 40 эссе Task 2 на 25–30 разных заданий: «чистая» основа (написана моделью уровня ~Band 8, проверена вторым вендором) + 6–10 ошибок, вставленных кодом из каталога (артикли, время, согласование, предлог, коллокация, форма слова, орфография, run-on) | 20 / 20 | Точный: список вставленных ошибок с офсетами |
| **G** — граничные случаи | ≤ 20 слов, 150–200 слов, не по теме, не тот язык, списки вместо текста, копия задания, инструкция модели внутри эссе, заученный шаблон, необычный, но корректный стиль | 10 / 10 | Ожидаемое поведение по правилам D1 и D §2 |
| **R** — стабильность | 10 эссе из S и H1, по 5 повторов | — / 10 | Разброс между повторами |
| **H1** — ELLIPSE (CC BY 4.0) | Школьные эссе ELL, два оценщика, 6 аналитических признаков | 50 / 100 | Ранговое согласие: cohesion ↔ CC, vocabulary + phraseology ↔ LR, grammar + syntax + conventions ↔ GRA |
| **H2** — EWCCE (CC BY 4.0, если файлы доступны) | 200 рукописных эссе, полосы IELTS по 4 критериям от двух преподавателей | 50 / до 150 | Расхождение с каждым оценщиком и со средним; согласие самих оценщиков — потолок |

Подготовка (бесплатно или почти): каталог вставок и генератор S на TS в этом репо; расшифровка H2 — модель с изображением + выборочная
вычитка (≈ $2); тексты третьих лиц в репозиторий не кладутся (`benchmarks/README.md`).

## 3. Метрики и пороги (гипотезы, утверждает владелец)

| Метрика | Набор | Порог для «годно к выпуску как разбор» |
|---|---|---|
| Полнота по вставленным ошибкам серьёзности moderate/major | S | ≥ 0.70 |
| Точность находок (доля верных среди отмеченных) | S (+ ручная выборка на H1) | ≥ 0.85 |
| Ложные исправления (правильный текст «исправлен» неверно) | S, H1 выборка | ≤ 5 % находок |
| Цитаты, не совпавшие с текстом, после шага 5 | все | 0 (детерминированно) |
| Правила D1 сработали как ожидалось | G | 100 % |
| Инструкция внутри эссе не исполнена | G | 100 % |
| Разброс середины диапазона критерия между повторами | R | SD ≤ 0.5 полосы |
| Ранговая корреляция (Спирмен) с человеческими признаками | H1 | ≥ 0.5 по каждой паре |
| В пределах ±1 полосы от среднего двух оценщиков | H2 | ≥ 80 % и не хуже согласия оценщиков между собой более чем на 10 п. п. |
| Стоимость одной оценки Task 2 | все | ≤ $0.10 ожидаемо (цель для цены пакетов) |
| Время до результата | все | p90 ≤ 60 с |

Пороги баллов (H2) не делают оценку «калиброванной» в смысле ADR-003 — оценщики не экзаменаторы IELTS. Они задают ширину
ориентировочного диапазона и решают, показывать ли число вообще.

## 4. Этапы и смета

Оценка стоимости одной оценки Task 2 (эссе ~300 слов, руководство ~1 200 токенов на критерий, 4 критерия + проверка):
вход ≈ 8–10 тыс. токенов, выход ≈ 3–7 тыс. (с рассуждением).

| Модель оценки | ≈ $ за оценку (P2 + проверка) |
|---|---|
| Claude Haiku 5.5 | 0.01 |
| Claude Sonnet 5.5 | 0.09 |
| GPT-5.4 | 0.13 |
| Claude Opus 5.5 | 0.18 |

| Этап | Что | Прогонов | ≈ $ ожидаемо |
|---|---|---|---|
| A. Выбор пайплайна | P0 / P1 / P2 × (Haiku, Sonnet) × dev (S 20 + G 10 + H1 30), с проверкой и без | ~600 | 20 |
| B. Выбор модели | Лучший пайплайн × (Opus, GPT-5.4) × тот же dev | ~120 | 20 |
| C. Финал | 2 конфигурации-финалиста × test (S 20 + G 10 + H1 100 + H2 до 150) + R (2 × 50) | ~660 | 40 |
| Подготовка | Основы для S, расшифровка H2, проверка руководства (P1.1) | — | 5 |
| **Итого** | | | **≈ 85**, предлагаемый лимит **$100** |

Если Haiku 5.5 пройдёт пороги, этап C и сама эксплуатация будут в разы дешевле.

## 5. Порядок работ Фазы 1

1. P1.1 Руководство по оценке Task 2 своими словами (D §3) — черновик, проверка вторым вендором, «да» владельца.
2. P1.2 `Exam\Bench` в MultiAdmin: датасеты эссе, прогон пайплайнов на `GenerationRun`/`StepRunner`/`MeteredLlm`
   (с `feature = exam`), метрики — после gate Фазы 0 и с разрешения на изменения MultiAdmin.
3. P1.3 Наборы S и G (генератор и каталог вставок в этом репо), загрузка H1, проверка и расшифровка H2.
4. P1.4 Этапы A → B → C, у каждого замороженный манифест и «да» с лимитом.
5. P1.5 Отчёт бенчмарка (`benchmarks/REPORT.md`): решение «разбор + ориентировочные полосы», «только разбор» или «доработать».
