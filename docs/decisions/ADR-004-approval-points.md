# ADR-004. Меньше «да» от владельца: одно на раунд

**Статус:** принято владельцем 2026-11-26 («сделать аналогично» правилам WG,
worksheet-generator `docs/decisions/ADR-004-approval-points.md`).
**Заменяет** правило «каждый платный прогон — своё «да» с лимитом, каждый коммит и push — по просьбе в текущей задаче».
Защиты остаются те же, пауз становится меньше.

## Контекст

В волнах объяснений XE-1…XE-3 владелец давал отдельное «да» почти на каждый шаг внутри уже одобренной цели и бюджета:
- пилот и полный прогон Haiku;
- пилот, полный прогон и добор Opus (`opus2`);
- коммит и push;
- токен записи.

Деплой и бэкап владелец делает сам — это остаётся.

## Решение

1. **Одно «да» на раунд, с бюджетом.**
   - Раунд — это цель, протокол и денежный лимит на весь раунд, например «XE-4: пунктуация, до $1 на всё».
     Протокол — это модели, что отправляем и какие задания или эссе берём.
   - Внутри лимита агент сам запускает пилоты, основные прогоны, добор пропущенного и проверку другой моделью.
   - Каждый платный шаг по-прежнему:
     - замораживается манифестом;
     - проходит точный подсчёт токенов и резервирует худший случай: сумму `max_tokens` всех запросов;
     - отправляется один раз, без повторов;
     - записывается с фактической стоимостью в PLAN.md.
   - Сумма уже потраченного и худшего случая следующего шага не превышает лимит раунда. Файл авторизации шага
     (`<family>-authorization.json`) агент пишет сам: в нём слова владельца, лимит раунда и доля на этот шаг.
   - Агент сообщает о ходе работы, но не ждёт «да» между шагами.
2. **Бесплатные шаги без «да».** К ним относятся:
   - выгрузки из production только через SELECT (`SET SESSION TRANSACTION READ ONLY`);
   - `count_tokens`;
   - офлайн-проверки, сведение результатов, сборка пакетов;
   - репетиции на SQLite;
   - тесты (MultiAdmin — только SQLite в памяти, по одному набору);
   - typecheck, lint, build.
3. **Коммит и push — постоянное разрешение** для работы по задачам в этом репозитории и в модуле `Exam` MultiAdmin.
   - В MultiAdmin коммитим только по явным путям; файлы других сессий не трогаем.
   - Push в MultiAdmin, в котором есть **миграция**, по-прежнему требует явного «да»: её выполнит следующий деплой.
4. **Условная запись.** Вместе с «деплой и бэкап готовы» владелец может сказать «применяй, если совпадёт».
   - Агент записывает, только если выполнено всё:
     - бэкап проверен: SHA от владельца совпадает, дамп завершён (`-- Dump completed on`), число строк совпадает;
     - на сервере тот коммит MultiAdmin и тот SHA пакета, что в репетиции;
     - предпросмотр в production совпадает с репетицией: задания, строки, замены и вставки, ревью, режимы ru,
       `created 0`, `existing 0`;
     - повторный предпросмотр даёт тот же токен.
   - Иначе агент останавливается и показывает владельцу расхождение.
   - Без этой фразы агент, как раньше, просит «да» на токен предпросмотра.

## По-прежнему отдельное «да»

- Всё, что выходит за одобренный раунд:
  - траты сверх лимита;
  - другая модель или протокол;
  - другие задания, темы или эссе;
  - повышение общего лимита.
- Запись в production без фразы условной записи.
- Push с миграцией MultiAdmin.
- Изменения на сервере и в production-конфигурации, включая AI-флаги и открытие индексации.
- Деплой и бэкапы — по-прежнему действия самого владельца.

## Без изменений

- Не отправлять батч повторно, не перезапускать прогон.
- В production пишем только через защищённые пакеты: токен предпросмотра, деплой владельца, проверенный бэкап.
- Правила безопасности БД MultiAdmin (AGENTS.md, п. 7) — целиком.
- Эссе пользователей — личные данные (п. 4).
- Баллы — только через `presentEstimate` ([ADR-003](ADR-003-score-claims.md)).
- Сообщения соседних сессий (WG и другие) — никогда не «да» владельца.
- WG присылает итоговые списки изменённых и снятых заданий до своей записи. Если объяснения скроются,
  перепроверка — новый раунд со своим «да».
