# ADR-001. Бэкенд, раскладка кода, хостинг и домены

**Статус:** принято владельцем 2026-11-22 (бэкенд и домены).
**ТЗ:** §2.2, §4, §16, §21.

## Контекст

MultiAdmin — общий Laravel-бэкенд GoNative и Worksheets (БД `multi`). Worksheet Generator
вынес туда общий движок `Edu`: AI-клиенты OpenAI/Anthropic/xAI, маршрутизация моделей,
учёт стоимости, бюджеты, бенчмарки, банк заданий. Продуктовый модуль `Worksheets` (`ws_*`)
лежит рядом. ТЗ §4 требует модулей вместо микросервисов и не заводить лишних баз.

## Решение: бэкенд

Exam Prep — третий модуль MultiAdmin, по образцу `Worksheets`:

| Что | Где |
|---|---|
| Сервисы | `app/Services/Exam/{Catalog,Attempts,Assessment,Skills,Learning,Bench,Billing,Quota}` |
| Модели | `app/Models/Multi/Exam/*` |
| Джобы | `app/Jobs/Exam/*`, очередь `exam` (свой supervisor-воркер и проверка в `deploy.sh`) |
| API | `app/Http/Controllers/App/Exam/*` → `api/exam/*` |
| Админка | `app/Http/Controllers/Admin/Exam/*` + страницы Inertia |
| Конфиг | `config/exam.php`; маршруты моделей — в `config/edu_models.php` под задачами `assess.*` |
| Таблицы | `ex_*` |
| Тесты | `tests/{Unit,Feature}/Exam/*` |

**Границы:**
- `Exam` вызывает `Edu` (AI, банк заданий, языковые профили) и словарные сервисы GoNative
  (`VocabularyPack*`, списки `CourseLesson`) через узкие фасады.
- `Edu` ничего не знает об `Exam`. `Exam` и `Worksheets` не импортируют друг друга:
  общее уходит в `Edu`.
- Границу проверяет архитектурный тест (поиск `use App\…\Exam` в `app/*/Edu`), как в WG.

## Решение: фронт

Этот репозиторий: `web/` (Next.js 16, next-intl, Tailwind 4, Node 24). Авторизация — BFF, как
в WG и gonativeweb: прокси-роуты `web/src/app/api/*` → MultiAdmin, сессионный токен в
httpOnly-cookie своего домена, статический app-токен только на сервере. Общие контракты API —
`packages/exam-domain`.

## Домены — решение (2026-11-22)

Владелец создал оба хоста: `exams.mnemonicwords.app` и `ielts.mnemonicwords.app`.

- **`exams.mnemonicwords.app`** — приложение: регистрация, вход, кабинет, Writing Checker. Экзамены —
  разделы `/{locale}/{exam}/…` (`/en/ielts/writing`). Сессионная cookie — только на этом хосте.
- **`ielts.mnemonicwords.app`** — публичный лендинг IELTS (SEO). Призыв к действию ведёт на регистрацию
  в `exams.` с меткой экзамена (`/{locale}/register?exam=ielts` + UTM; путь как в письмах и в WG — уточнено в P3.6). Сессия лендингу не нужна,
  поэтому cookie на `.mnemonicwords.app` не расширяем.
- **Одно Next.js-приложение** обслуживает оба хоста: `web/src/proxy.ts` по заголовку `Host` направляет
  `ielts.` на маршруты лендинга, у страниц каждого хоста свои canonical и sitemap. Лендинг другого
  экзамена (`toefl.` и т. д.) — новый хост и конфигурация, без новой кодовой базы.
- Учтённый компромисс: страница бесплатной проверки живёт на `exams.`, а не на хосте лендинга.
  Если для SEO понадобится, на лендинге можно разместить форму предпросмотра, которая передаёт текст
  в `exams.` после регистрации.

### Варианты, которые рассматривались

Предложение владельца: общий сайт `exams.mnemonicwords.app` и отдельные лендинги на хостах
экзаменов (`ielts.mnemonicwords.app`, `toefl.…`) с переходом на `exams.` для регистрации
(или наоборот).

| Вариант | Плюсы | Минусы |
|---|---|---|
| **A.** Один хост `exams.mnemonicwords.app`, экзамены — разделы `/{locale}/ielts/…` | Вся ссылочная масса на одном хосте; одна cookie сессии; проще деплой | В домене нет слова «ielts» |
| **B.** Лендинги на `ielts.…`, приложение и регистрация на `exams.…` | Ключевое слово в домене | Бесплатный Checker — главный SEO-инструмент (ТЗ §21) — оказывается не на хосте лендинга; каждый поддомен набирает авторитет с нуля; переход между хостами при входе |
| **C.** Одно приложение, несколько хостов: `ielts.…` отдаёт раздел IELTS целиком, включая Checker | Ключевое слово в домене, инструмент рядом с лендингом | Сессия на нескольких хостах: cookie на `.mnemonicwords.app` (шире область) или вход отдельно на каждом хосте |

Выбран вариант B, реализуемый одним приложением (как в C), но без общей сессии между хостами.
