# G. Интеграция лексики GoNative (P0.1)

**Статус:** черновик v1 (2026-11-23). Только чтение кода MultiAdmin, gonative и gonativeweb и агрегатные
SELECT по локальной sandbox-базе (синхронизирована с production, данные Edu — по 2026-11-16).
**ТЗ:** §11, §19, §26 G. **Основано на:** [A](A-gonative-assessment.md), [ADR-002](../decisions/ADR-002-accounts-and-billing.md).

## 1. Итог

| Вывод | Следствие |
|---|---|
| В GoNative есть словарные паки под **14 экзаменов**, не только IELTS | Лексическая часть будущих экзаменов (ТЗ §5) уже есть |
| Паки IELTS Academic и General **переведены на ru и uk полностью**, на всех уровнях A1–C2 | Персональные списки с переводами работают сразу для en/ru/uk |
| Списки из паков — обычные списки GoNative («Your Lessons», `course_id = 6`) с меткой `attributes.source = vocabulary_pack`; в sandbox их 204 | Создаём списки тем же способом с меткой `source = exam_prep`; изучение и SRS — средствами GoNative |
| Лимит слов проверяет только сервер (`LearningWordsQuotaService`); клиенты показывают серверный статус и обрабатывают ответ 402 | Снять лимит для подписчиков Exams (ADR-002) можно **на сервере, без релиза приложений** |
| В словаре есть слова и устойчивые фразы, но почти нет свободных коллокаций | Коллокации не кладём в списки GoNative: практикуем упражнениями Edu и показываем в контексте |
| `createWordsFromText` добавляет новые слова пользователей прямо в общий словарь без статуса проверки | Exam Prep этот путь **не использует** (ТЗ §11.5) |

### 2.2 Тематическая лексика

`lexical_domains` (23) → `lexical_clusters` (357): повседневные и профессиональные темы (семья, жильё, здоровье,
работа, учёба, технологии, бизнес, IT, маркетинг…), уровни **до B2**, плюс фразовые глаголы и устойчивые
сочетания с предлогами до B1. Академических тем уровня C1 (экология, общество, власть, глобализация) нет —
для IELTS Task 2 основной источник остаются паки.

### 2.3 Словарь и коллокации

Проверка 25 типичных выражений IELTS в `dictionary_en` (247 тыс. записей, 4 872 фразы): отдельные слова
(*crucial, detrimental, mitigate, tackle, alleviate, furthermore, whereas*) и устойчивые фразы (*on the other hand,
in addition, public transport*) есть. Свободных коллокаций (*significant challenge, play a crucial role,
raise awareness, pose a threat, have a detrimental effect, a substantial number of*) нет.

### 2.4 Списки, повторение, квота

- `VocabularyPackListBuilderService::createLearningLists()`: создаёт `CourseLesson{Lang}` в курсе «Your Lessons»,
  `CourseWord{Lang}` и `PiggyBank{Lang}`, режет список по остатку квоты (целыми списками), резервирует квоту
  в транзакции, отмечает слова пака как `added_to_lists`.
- Повторение — календарь списков (`addLessonToCalendar`, `RepetitionSchedule`), тренировки — как у любых списков.
- Квота: `LearningWordsQuotaService` (100 слов для бесплатных, Premium = `user_data.premium_ends_at`). Статус
  квоты сервер кладёт в данные пользователя (`learning_words_quota`), клиенты обрабатывают код
  `LEARNING_WORDS_LIMIT_EXCEEDED` (HTTP 402).
- Клиенты определяют Premium сами по `premium_ends_at` (mobile: `store/slices/user.ts`, `AppWrapper.tsx`;
  web: `lib/premium-access.ts`). Значит, функции, закрытые Premium на клиенте (офлайн-режим и др.), подписка
  Exams не откроет без клиентских изменений — что и соответствует решению «нужные лимиты, не полный Premium».
- Серверные проверки Premium есть ещё у подкастов (`PodcastAccessService`), книг (`BookController`) и
  `RetentionRescue`. Для подготовки к экзамену они не нужны.
- Ежедневный лимит упражнений для бесплатных (`gonative/docs/free-learning-limits-plan.md`) пока только план.
  Когда его введут, он должен проверять ту же «доступ к обучению» (п. 3.3).

## 3. Предлагаемая интеграция

### 3.1 Поток (ТЗ §11.3)

1. Оценка даёт находки `vocabulary.*` с цитатами (повторы, неточный выбор слова, коллокации, регистр).
2. Модель предлагает замены и выражения **в контексте предложения пользователя**. Код сопоставляет каждое
   предложение со словарём: остаётся только то, что есть в `dictionary_en`, предпочтительно — в паке IELTS
   на уровне пользователя ±1.
3. Исключаем известное: статусы слов пака (`known`, `added_to_lists`) и слова, уже лежащие в списках пользователя.
4. Список создаётся обобщённым построителем (п. 3.2) с `attributes.source = exam_prep`, ссылкой на попытку и
   навыки. Квота — через «доступ к обучению» (п. 3.3).
5. Изучение — в GoNative mobile и web без изменений. В Exam Prep — ссылка на список и прогресс.
6. Коллокации и выражения, которых нет в словаре, в списки GoNative не попадают:
   - практика — упражнениями Edu (подбор коллокации, исправление ошибки; см. [H](H-edu-integration.md));
   - в разборе — с примером в контексте и переводом на язык объяснений;
   - перенос проверенных коллокаций в общий словарь — отдельный модерируемый процесс (вопрос владельцу).

### 3.1a Перенос коллокаций в общий словарь (решение владельца 2026-11-23: «да»)

Проверенные коллокации и выражения переносятся в `dictionary_en` как фразы, после чего их можно учить
списками GoNative. Перенос модерируемый, не автоматический (ТЗ §11.5):

1. **Кандидаты** — Edu senses (`edu_senses`, провенанс и статус) из двух источников: предложения разбора эссе,
   которые повторяются у разных пользователей, и плановое наполнение по темам IELTS.
2. **Проверка** — два вендора независимо: естественность и частотность выражения, уровень CEFR, пример в контексте.
   Переводы ru/uk — через существующий консенсус переводов (`config/translation_consensus.php`).
3. **Очередь модерации** в админке MultiAdmin: принять / отклонить / исправить. Без принятия ничего не попадает
   в общий словарь.
4. **Перенос** принятого — фраза в `dictionary_en` (`is_phrase`) с отметкой происхождения (AI + модерация),
   переводами и примером. Повторный перенос того же выражения идемпотентен.
5. До переноса выражение в Exam Prep показывается в разборе и практикуется упражнениями Edu.

Реализация — Фаза 4, в MultiAdmin. Объём ручной модерации — отдельная оценка: начинать с небольших
партий самых частотных выражений.

### 3.2 Расширения MultiAdmin (после gate Фазы 0)

| # | Что | Объём |
|---|---|---|
| V1 | Вынести из `VocabularyPackListBuilderService` общий построитель «список из id словаря + атрибуты источника»; пакам и Exam — по вызову | Рефакторинг без смены поведения пакам, тесты на совпадение |
| V2 | `LearningWordsQuotaService`: «доступ к обучению» = Premium **или** активное право `exams` в `product_entitlements`; статус для таких пользователей — без лимита (`tier` — уточнить, как его показывают клиенты) | Маленькая правка + тесты; релиз приложений не нужен |
| V3 | Индекс/запрос «слова пользователя во всех его списках» для исключения известного | Чтение, без миграций, если хватает индексов `course_word_*` |

### 3.3 Проверить при реализации

1. Как mobile и web показывают `learning_words_quota` с `limit = null` и нестандартным `tier` (визуальная проверка).
2. Видимость списков с `source = exam_prep` в web (`hooks/useCourses.ts`, `useCourseData.ts`) — код грузит
   курсы и списки пользователя целиком, но интерфейс проверить вручную.
3. Поведение по окончании Premium (и, значит, Exams): списки сохраняются, добавление новых слов снова
   ограничено квотой — подтвердить на sandbox.
