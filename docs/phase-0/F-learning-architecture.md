# F. Персональное обучение: от слабостей к плану

**Статус:** черновик v1 (2026-11-23). **ТЗ:** §10, §13, §26 F. **Основано на:** [C](C-exam-engine-architecture.md) §5–6,
[G](G-vocabulary-integration.md), [H](H-edu-integration.md).

## 1. Принципы

1. **Слабость — это закономерность, а не одна ошибка** (ТЗ §10.2): учитываем число наблюдений, давность и неопределённость.
2. **Навыки и критерии экзамена — отдельно** (ТЗ §10.3): прогресс по `grammar.articles` и прогресс по GRA считаются раздельно.
3. **Детерминированное ядро, AI — только для формулировок.** Приоритеты, расписание и подбор ресурсов считает код;
   модель может объяснить план человеческим языком.
4. **Ничего не обещаем по срокам** (ТЗ §13.6): показываем, что сделано и что осталось, а не «Band 7 через 30 дней».

## 2. Профиль навыков

**Наблюдение** (`ex_skill_observations`, только добавление): навык, источник (находка оценки / ответ практики),
серьёзность, вес, время, ссылка на попытку или сессию практики.

**Состояние навыка** (`ex_skill_states`, пересчитывается из наблюдений):

| Поле | Как считается |
|---|---|
| Частота ошибок | Взвешенные по серьёзности ошибки на 100 слов по последним попыткам, с затуханием по давности (полупериод — 3 попытки) |
| Практика | Доля верных ответов по темам Edu этого навыка за последние 30 дней |
| Статус | `insufficient_evidence` (меньше 2 попыток или меньше 3 наблюдений) → `needs_practice` (частота выше порога уровня) → `improving` (частота упала на ≥ 30 % к предыдущему окну) → `ok` |
| Уверенность | Растёт с числом попыток и слов; показывается пользователю словами («мало данных») |

Пороги — гипотезы, уточняются на реальных данных (без AI, чистая статистика).

## 3. Рекомендации

Ранжирование кандидатов (код):

```
приоритет = серьёзность × частота × связь с самым слабым критерием × (1 − уже сделано за неделю)
```

| Вид | Источник | Как выполняется |
|---|---|---|
| Грамматическая практика | Навык → темы Edu ([H](H-edu-integration.md) §3, §5) | Сессия 10–15 заданий онлайн (после появления проверки ответов в Edu) |
| Лексика | Находки `vocabulary.*` → слова словаря / паков ([G](G-vocabulary-integration.md) §3.1) | Список в GoNative, изучение там же |
| Работа над своими ошибками | Находки последней попытки | Переписать 3–5 своих предложений; проверка — сравнение с исправлением + дешёвая AI-проверка |
| Новое письмо | Слабые `task.*` / `coherence.*` + тема, которую ещё не писал | Задание из библиотеки того же типа |
| Повторная оценка | Каждые 2–3 попытки или раз в 2 недели | Новое эссе, сравнение трендов по критериям с учётом диапазонов |

Одновременно открыто не больше 3–5 рекомендаций; выполненные и отклонённые сохраняются.

## 4. План подготовки

- **Входы:** профиль (экзамен, цель, дата экзамена, минут в неделю — всё необязательно), состояние навыков, тренд
  критериев, доступные ресурсы (банк, паки), выполненное.
- **Шаблон недели** (код): N писем (по времени до экзамена), M грамматических сессий, ежедневная лексика в GoNative
  (интервальное повторение GoNative), одна повторная оценка в 1–2 недели. Без даты экзамена — ровный режим.
- **Версии:** план хранится версиями (`ex_learning_plans`). Пересчёт — после новой оценки, раз в неделю или при смене
  профиля, но не после каждого действия (ТЗ §13.5).
- **Близость экзамена:** за 2 недели — больше полных заданий на время, меньше новой лексики.

## 5. Что в MVP, что позже

MVP (Фаза 3): только наблюдения навыков и простая сводка «частые ошибки» на странице результата. Рекомендации, практика,
лексические списки и план — Фаза 4 ([K](K-mvp-spec.md)).
