## 2. P4.1–P4.3. Основа в MultiAdmin (G §3.2: V1–V3)

### P4.1. Доступ к обучению по праву `exams` (V2)

- `LearningWordsQuotaService::status()` и `reserve()`: без лимита, если Premium **или** активное платное право `exams`
  (`ProductEntitlement::hasAccess(user, 'exams', exam.paid_plan)` — ручные доступы `products:grant` и будущий Paddle).
- Статус для такого пользователя: `tier = 'exams'`, `limit = null`, `remaining = null`. Premium остаётся `premium`.
- `isPremium()` не меняется.
- По окончании права списки остаются, новые слова снова идут в бесплатную квоту (G §3.3 п. 3) — тест.

### P4.2. Известные слова (V3)

`Learning\KnownWords::filter(userId, lang, dictionaryIds)` — убирает слова, которые уже есть в любом списке пользователя
(`course_word_{lang}`, кроме `deleted`) или отмечены в паках как `known` / `added_to_lists`. Только чтение.

### P4.3. Общий построитель списков (V1)

`Learning\LearningListWriter::create(userId, lang, dictionaryIds, baseName, maxWords, attributes)` — то, что сейчас
внутри `createLearningLists`: курс «Your Lessons», уроки по `maxWords` слов, `CourseWord` + `PiggyBank`, резерв квоты
в той же транзакции, обрезка по остатку квоты целыми списками.
- Паки вызывают его со своими атрибутами (`source = vocabulary_pack`, уровень пака) и своей нумерацией; статусы слов
  пака и прогресс пака обновляют сами, как сейчас.
- Сначала тест, фиксирующий нынешнее поведение паков (SQLite, таблицы GoNative создаются в тесте), потом вынос.

## 3. P4.4. Слова из разбора → список в GoNative (G §3.1)

Без AI, по находкам уже готового разбора.

1. **Кандидаты.** Находки `vocabulary.*` вида «ошибка» и «можно улучшить» с исправлением. Из исправления берём слова,
   которых нет в цитате (то, что пользователь должен был написать), и всё исправление целиком, если это фраза.
2. **Словарь.** Каждое слово приводится к словарной форме простыми правилами английской морфологии
   (`outweighs` → `outweigh`, `studies` → `study`, неправильные глаголы — по `verb_lemmas`) и ищется в `dictionary_en`.
   Фраза — только если она есть в словаре целиком. Чего нет в словаре, в список не идёт.
3. **Отбор.** Служебные слова не берём. Слова из пака IELTS (Academic или General — по экзамену) — первыми; уровень
   пака не ниже уровня, к которому относится ориентировочный диапазон LR, минус один.
4. **Исключение известного** — P4.2.
5. **Создание списка** — P4.3, имя «IELTS Writing · <дата>», атрибуты `source = exam_prep`, `attempt_uuid`, навыки.
   Квота — P4.1: бесплатный пользователь Exams тратит свои 100 слов GoNative.
6. **Повторно** для той же попытки список не создаётся: ответ возвращает уже созданный.

**API** (за флагом А, как остальные `api/exam/*`):
- `GET attempts/{uuid}/vocabulary` — до 15 слов с переводом на язык перевода профиля, навыком и id находки; статус
  квоты; ссылка на уже созданный список.
- `POST attempts/{uuid}/vocabulary/list` — создаёт список из выбранных слов (по умолчанию все).

**Сайт:** блок «Слова для GoNative» на странице результата: слова с переводом, кнопка «Добавить в GoNative», после —
ссылка на приложение. Без слов блок не показывается.

**Личные данные:** в списке только id слов словаря и uuid попытки, текста эссе нет. Удаление данных Exams списки
GoNative не трогает (K §3, критерий 8): `attempt_uuid` остаётся в атрибутах урока как непрозрачный id, который после
удаления ни на что не указывает (вопрос 2).

## 4. P4.5–P4.6. Рекомендации и план (F §3–§4)

### P4.5. Рекомендации

Код, без AI. Одновременно открыто не больше 4. Источники — профиль навыков и последний разбор.

| Вид | Когда | Что видит пользователь |
|---|---|---|
| `vocabulary_list` | В последнем разборе есть слова P4.4, список ещё не создан | «Добавьте N слов из разбора в GoNative» |
| `rewrite` | В последнем разборе есть ошибки | 3–5 своих предложений с ошибками: переписать и сверить с исправлением (самопроверка; AI-проверка — позже, вопрос 4) |
| `new_essay` | Навык `task.*` или `coherence.*` в статусе `focus` / `watch` | Задание библиотеки того же типа, которое пользователь ещё не писал, с навыком, на который смотреть |
| `reassess` | 2 попытки с прошлой оценки или 14 дней | «Напишите новое эссе — сравним с прошлым» |

Приоритет: `серьёзность × частота навыка × (1 − сделано за неделю)`, как в F §3. Грамматическая практика из банка —
когда будет проверка ответов в Edu (пункт 2 порядка Фазы 4).

Хранение: таблица `ex_recommendations` (новая, добавочная миграция): вид, навык, ссылка на попытку, статус
`open` / `done` / `dismissed`, даты. Без текста эссе.

API: `GET recommendations`, `POST recommendations/{uuid}/done`, `POST recommendations/{uuid}/dismiss`.
Сайт: блок «Что делать дальше» на странице прогресса и под результатом.

### P4.6. План недели

- Входы: `exam_date`, `weekly_minutes` (необязательные, спрашиваем в настройках), профиль навыков, открытые рекомендации.
- Шаблон недели — код: эссе в неделю по времени до экзамена (больше 8 недель — 1, 3–8 — 2, меньше 3 — 3, на время),
  повторная оценка раз в 1–2 недели, ежедневные слова в GoNative, исправление своих ошибок после каждого разбора.
  Без даты экзамена — 1 эссе в неделю.
- Пересчёт — после новой оценки или смены профиля, не после каждого действия. Хранение версиями — `ex_learning_plans`.
- Обещаний по срокам и баллам нет (F §1 п. 4).

## 5. P4.7. Модерация коллокаций (G §3.1a)

1. **Кандидаты** — таблица `ex_collocation_candidates`: выражение (не текст эссе — исправление модели), навык, число
   разных пользователей, у которых оно встретилось, первый и последний раз. Пополняется кодом при разборе: фразы
   из исправлений `vocabulary.collocations` / `word_choice`, которых нет в `dictionary_en`. Порог для очереди —
   2+ пользователя.
2. **Проверка** двумя вендорами — естественность, уровень CEFR, пример, переводы ru/uk через консенсус переводов.
   **Платно, смета перед запуском** (вопрос 5).
3. **Очередь в админке MultiAdmin** (`/admin/exams/collocations`): принять / исправить / отклонить.
4. **Перенос** принятого в `dictionary_en` как фраза с отметкой происхождения, переводами и примером; идемпотентно.
   Запись в общий словарь — только кнопкой модератора.

Сначала шаги 1 и 3 без AI (сбор и очередь), шаг 2 — после сметы, шаг 4 — после проверки на sandbox.

## 9. Отложено (решения владельца 2026-11-25)

1. **Тост лимита слов в клиентах GoNative.** Mobile (`LessonWordsScreen` и др.) показывает «лимит 100 слов» всем, у кого
   нет Premium на клиенте; подписчику Exams лимит не действует (`tier = 'exams'`). Правка: решать по серверному
   `learning_words_quota` (`tier`, `limit = null`), а не по `hasPremium`. Нужен релиз mobile; web — отдельным деплоем
   GoNative. До правки — только визуальная проверка.
2. **AI-проверка переписанных предложений** («Исправьте сами»). Ученик вводит свой вариант, дешёвая модель отвечает:
   верно / ошибка осталась / новая ошибка, с одной фразой объяснения на языке объяснений. Около $0.002 за проверку,
   лимит в квоте Exams, текст — личные данные (не логировать, удалять вместе с попыткой). Перед запуском — смета,
   небольшой замер на синтетических предложениях и «да» владельца с лимитом.
