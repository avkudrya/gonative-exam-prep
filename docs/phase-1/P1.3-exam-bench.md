# P1.3. `Exam\Bench` — бенчмарк оценки эссе в MultiAdmin

**Статус:** готово 2026-11-23, локальный коммит MultiAdmin `47c1ccb1` (без push). Платных вызовов не было.
**Основано на:** [D](../phase-0/D-assessment-strategy.md) §2 (пайплайн), [E](../phase-0/E-benchmark-plan.md) §2–4 (наборы, метрики, этапы),
[P1.1](P1.1-assessment-guide.md) (руководство и правило полосы).

## 1. Что сделано

| MultiAdmin | Что делает |
|---|---|
| `config/exam.php` | Маршруты моделей по умолчанию (`exam.assess` — Haiku 5.5, `exam.validate` — GPT-5.4 mini → Haiku), версии промптов, ключи навыков, порог копирования задания (8 слов) |
| `app/Services/Exam/Text/ResponseText` | Нормализация, подсчёт слов `whitespace-v1`, офсеты в кодовых точках — как `text.ts`, включая Unicode-пробелы |
| `app/Services/Exam/Guide/AssessmentGuide` | Читает руководство из этого репо; полоса по ответам — то же правило, что `bandFromChecklist`, плюс два правила для сравнения (`top`, `share` ≥ 75 %) |
| `app/Services/Exam/Guide/CatalogRubric` | Рубрика и задание из `catalog/*.json`, сверка руководства с рубрикой |
| `app/Services/Exam/Assessment/RubricRules` | Шаг 1: не английский → Band 0; ≤ 20 засчитанных слов → Band 1; скопированное из задания (≥ 8 слов подряд) не засчитывается; флаги «нет абзацев», «списки», «недобор» |
| `…/AssessmentPrompts` | Промпты P0 (один вызов, прямые полосы), P1 (по критерию, прямая полоса), P2 (по критерию, чек-лист руководства), проверка находок |
| `…/AssessmentOutput` | Шаг 5: цитаты сверяются с текстом, недоказанные ответы не засчитываются, неполный чек-лист — критерий без полосы |
| `…/EssayAssessor` | Пайплайн целиком: правила → AI → проверки → проверка находок другим вендором; каждый вызов — идемпотентный шаг прогона под его бюджетом |
| `app/Services/Exam/Bench/*` | Замороженный набор, прогон с возобновлением и делением бюджета, оценка стоимости без вызовов, метрики |
| `exam:bench:run`, `exam:bench:report` | Команды: по умолчанию холостой прогон с оценкой; платный — только `--apply` с явным `--budget` |
| Тесты | `tests/Unit/Exam` (8), `tests/Feature/Exam` (6): SQLite, подменённые провайдеры. Архитектурный тест: Edu не зависит от `Exam` |

## 2. Решения в коде

1. **Недоказанное не считается.** «Выполнено» без нужной цитаты → не выполнено; «не выполнено» без цитаты → выполнено
   (недоказанная претензия не снижает полосу). Ограничитель с цитатой без цитаты не применяется. Всё это считается
   в метрике `evidenceMissing`.
2. **Цитата не найдена — находка отбрасывается** (`quoteNotFound`). После шага 5 несовпавших цитат в результате нет — порог E §3 выполняется по построению.
3. **Абзацы проверяет код:** текст одним блоком включает ограничитель CC без вопроса к модели.
4. **Не английский текст — Band 0 при любой длине**, затем правило ≤ 20 слов на засчитанных словах. Язык —
   эвристика `lang-v1` (доля латиницы и служебных слов английского); её точность проверит набор G.
5. **Сбой вызова или конец бюджета** → критерий без полосы, прогон `partial`, повторных платных вызовов нет. При
   следующем запуске такие прогоны продолжаются, уже оплаченные шаги не повторяются. `partial` из-за ответа модели
   (полоса вне шкалы, неполный чек-лист) — окончательный результат и метрика.
6. **Ремонт ответа (D §2 шаг 5) отложен:** в бенчмарке важнее увидеть, как часто модель ошибается, чем исправлять. В продукт — по итогам этапа A.

## 3. Формат набора

**Манифест** (`benchmarks/datasets/<id>/manifest.json`; пути относительно манифеста):

```json
{
  "id": "exam-a-dev-1", "budgetUsd": 20,
  "guide": "../../../packages/exam-domain/guides/ielts-writing-task-2.v1.json", "guideSha256": "…",
  "catalog": "../../../packages/exam-domain/catalog/ielts-academic.json", "rubricKey": "ielts-writing-task-2",
  "items": "items.jsonl", "itemsSha256": "…", "select": {"split": "dev", "sets": ["S", "G", "H1"]},
  "feedbackLanguage": "en",
  "traitMap": {"coherence_cohesion": ["cohesion"], "lexical_resource": ["vocabulary", "phraseology"], "grammatical_range_accuracy": ["grammar", "syntax", "conventions"]},
  "cells": [{"key": "p2-haiku-val", "pipeline": "p2", "validate": true, "repeats": 1, "routes": {"exam.assess": [{"provider": "anthropic", "model": "claude-haiku-5-5", "reasoning_effort": "low", "max_output_tokens": 16000}]}}]
}
```

**Элемент** (`items.jsonl`, одна строка — одно эссе, текст уже нормализован):
`{id, set: S|G|R|H1|H2, split: dev|test, examKey, prompt, text, expected}`, где `expected` (всё необязательно):
`errors` [{start, end, skill, severity}] в кодовых точках — для S; `early` (`short_response` / `wrong_language` / null),
`flags` {singleParagraph, listForm, copiedPrompt, underLength}, `bands` {критерий или `task`: {min, max}} — для G;
`traits` — для H1; `raters` [{критерий: полоса}, …] — для H2.

Изменённое руководство или файл эссе → загрузчик откажется: новый `id`.

## 4. Метрики (E §3) — `metrics.json` и `report.md` по ячейкам

Стоимость (среднее, p90), задержка p90 (критерии параллельно + проверка), полнота и точность по вставленным ошибкам (S),
доля пройденных проверок правил и границ (G), разброс между повторами (R), Спирмен с признаками (H1), ±1 полоса от
среднего оценщиков и их собственное согласие (H2), счётчики целостности. Для P2 дополнительно: те же метрики
согласия для трёх правил полосы, доля противоречивых чек-листов и признаки, чаще всего блокирующие следующую полосу
(вопросы проверяющего P1.1). Полные результаты с цитатами — в `responses/` (не коммитится).

## 5. Холостой прогон на утверждённом руководстве

Одно эссе (~260 слов), P2 с проверкой, оценка без вызовов. «Ожидаемо» здесь — грубая доля потолка выходных токенов:

| Модель оценки | Ожидаемо | Худший случай | Смета E |
|---|---|---|---|
| Claude Haiku 5.5 | $0.03 | $0.07 | $0.01 |
| Claude Sonnet 5.5 | $0.26 | $0.70 | $0.09 |
| Claude Opus 5.5 | $0.51 | $1.36 | $0.18 |
| GPT-5.4 | $0.37 | $0.99 | $0.13 |

Расхождение со сметой E значимо для бюджета этапа A (там 300 оценок на Sonnet). **Предложение:** до этапа A — мини-замер
A0: 3 эссе × 4 модели P2 с проверкой + P0/P1 на Haiku, лимит **$5**. Он даст фактические токены, по ним пересчитаем
этапы A–C, а потолок выходных токенов чек-листа можно будет снизить.
